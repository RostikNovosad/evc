# Lexi — застосунок для вивчення англійської (особистий)

Документ для старту проєкту: ідея, архітектура, рішення, роадмапа. Станом на 2026-11-02.

---

## 1. Ідея

Сесія вивчення — це "урок". Користувач вводить окремі слова, ідіоми, фразові дієслова. На кожен ввід застосунок повертає картку: переклад, пояснення, приклади використання. Коли сесію завершують, зі всіх карток генерується PDF, а дані сесії очищаються.

### Потік користувача

1. Старт сесії (кнопка "Нова сесія").
2. Ввід слова/фрази в інпут, Enter.
3. Бекенд повертає картку (див. п. 5), UI додає її в список сесії.
4. Повтор кроків 2–3 стільки, скільки треба.
5. "Завершити сесію" → PDF зі всіма картками → очищення списку сесії.

### Не цілі (поки)

- Багатокористувацька робота, авторизація.
- Вправи/квізи/SRS (можливе розширення, див. п. 11).
- Мобільний застосунок (достатньо адаптивного вебу).

## 2. Рішення

### 2.1 Джерело даних: LLM (Gemini API)

Словникові API (Cambridge, Merriam-Webster, dictionaryapi.dev) не підходять як основа: Cambridge API доступний за заявкою, переважно для комерційних партнерів; решта безкоштовних слабкі на ідіомах і не дають українського перекладу. LLM віддає все одним запитом: тип запису, переклад, пояснення, приклади, нюанси.

- Модель за замовчуванням: `gemini-3.5-flash-lite` (або `gemini-3.1-flash-lite`, `gemini-2.5-flash-lite`). Модель задається змінною середовища, перемикання без зміни коду.
- Безкоштовний тариф існує, але **числа лімітів Google не публікує в документації**. Фактичні RPM/TPM/RPD дивитися в AI Studio → Rate limit для свого проєкту. Це перший пункт Фази 0.
- На безкоштовному тарифі запити можуть використовуватися Google для покращення продуктів. Для словникових слів це неважливо.
- Орієнтовна вартість на платному: ~300 токенів на вхід + ~400 на вихід → центи за сотні слів.

### 2.2 Стек: Next.js (App Router) + TypeScript

- Fullstack в одному репозиторії: UI + Route Handlers (`app/api/.../route.ts`).
- Деплой на Vercel без налаштувань. Ключ Gemini лежить тільки в серверних env-змінних.
- Nuxt теж підійде (Nitro server routes). Різниця непринципова; обрано Next.js через простіший деплой на Vercel і більше прикладів з Gemini SDK. Якщо більше подобається Vue, структура нижче переноситься 1 в 1.

### 2.3 Зберігання: браузер, без БД

Vercel serverless **не має постійної файлової системи**, тому "json-server на стороні проєкту" не працюватиме (файл не зберігається між викликами). Варіанти:

| Варіант                    | Плюси                                                | Мінуси                               | Рішення         |
| -------------------------- | ---------------------------------------------------- | ------------------------------------ | --------------- |
| `localStorage` / IndexedDB | нуль інфраструктури, ідеально для одного користувача | дані прив'язані до браузера/пристрою | **Основний**    |
| Supabase                   | синхронізація між пристроями, власний словник        | додаткова залежність, налаштування   | Опційно, Фаза 5 |
| Upstash Redis / Vercel KV  | серверний кеш відповідей, економія квоти             | ще один сервіс                       | Опційно         |
| json-server / файли        | —                                                    | не працює на Vercel                  | Відхилено       |

Два окремі сховища (важливо, щоб "очищення сесії" не вбивало кеш):

- `lexi:session` — список карток поточної сесії. **Очищається після генерації PDF.**
- `lexi:cache` — кеш відповідей за нормалізованим ключем (`trim().toLowerCase()`). **Не очищається** (або має TTL/ліміт розміру). Повторне слово не витрачає квоту API.
- (Опційно) `lexi:dictionary` — власний словник, куди користувач додає картки вручну.

Сховище загорнути в тонкий інтерфейс `Storage`, щоб пізніше замінити localStorage на IndexedDB чи Supabase без переписування UI.

### 2.4 PDF: на клієнті

`pdfmake` або `jsPDF` у браузері. Бекенд не потрібен. Потрібен шрифт із кирилицею (наприклад Roboto/Noto Sans, підключити як файл або base64).

## 3. Архітектура

```
Браузер
 ├─ UI (сесія, інпут, список карток)
 ├─ Storage (localStorage): session + cache
 └─ PDF generator
        │  POST /api/lookup { query }
        ▼
Next.js Route Handler (Vercel)
 ├─ валідація й нормалізація query
 ├─ (опц.) серверний кеш / rate-limit
 └─ Gemini API (structured JSON)
```

### Структура репозиторію

```
lexi/
├─ app/
│  ├─ api/lookup/route.ts      # POST: запит до Gemini
│  ├─ page.tsx                 # UI (Фаза 2+)
│  └─ layout.tsx
├─ lib/
│  ├─ gemini.ts                # клієнт, промпт, схема, виклик
│  ├─ schema.ts                # zod-схема + TS-типи Card
│  ├─ normalize.ts             # нормалізація query
│  └─ storage.ts               # інтерфейс Storage + localStorage-реалізація
├─ scripts/
│  └─ probe.ts                 # Фаза 0: пакетне тестування API
├─ .env.local                  # GEMINI_API_KEY, GEMINI_MODEL
└─ LEXI_PROJECT.md
```

### Змінні середовища

```
GEMINI_API_KEY=...           # з AI Studio, ніколи не в клієнті, не в git
GEMINI_MODEL=gemini-3.5-flash-lite
```

На Vercel задати в Project Settings → Environment Variables.

## 4. API контракт

### `POST /api/lookup`

Запит:

```json
{ "query": "break the ice" }
```

Успіх `200`:

```json
{ "card": { ... }, "meta": { "model": "...", "inputTokens": 0, "outputTokens": 0, "latencyMs": 0 } }
```

Помилки (тіло `{ "error": { "code": "...", "message": "..." } }`):

- `400` порожній/задовгий query (ліміт, напр., 100 символів).
- `429` ліміт Gemini вичерпано (передати `retryAfter`, якщо є).
- `502` Gemini повернув невалідний JSON / помилку.
- `500` решта.

`meta` потрібна на етапі дослідження (токени, затримка). Пізніше можна прибрати.

## 5. Схема картки

```ts
type Card = {
  query: string; // як ввів користувач
  headword: string; // нормалізована форма ("break the ice")
  type: 'word' | 'idiom' | 'phrasal_verb' | 'phrase' | 'unknown';
  partOfSpeech?: string; // для слів
  ipa?: string; // для слів, може бути відсутня
  translationUk: string; // основний переклад
  definitionEn: string; // коротке пояснення англійською (B1–B2)
  explanationUk: string; // пояснення українською, нюанси вживання
  register?: 'formal' | 'neutral' | 'informal' | 'slang';
  examples: { en: string; uk: string }[]; // 2–3 приклади
  relatedPhrases?: string[]; // синоніми/пов'язані вирази
  corrected?: string; // якщо виявлена помилка в написанні
  confidence: 'high' | 'medium' | 'low'; // самооцінка моделі
};
```

Валідація відповіді через `zod`. Якщо парсинг не вдався, одна повторна спроба, потім `502`.

### Промпт (чернетка)

System:

> You are a bilingual English–Ukrainian dictionary for an intermediate learner. For the user's input (a word, idiom, phrasal verb or phrase) return ONE JSON object matching the schema. Rules: detect the entry type; fix obvious typos and put the fixed form in `corrected`; give 2–3 natural, realistic example sentences with Ukrainian translations; explain nuance and register; if the input is not a real English expression, set type "unknown" and confidence "low" instead of inventing a meaning. Keep definitions short and simple.

Використати structured output: `responseMimeType: "application/json"` + схема відповіді в конфігу виклику (`@google/genai`). Точний синтаксис схеми звірити з поточною документацією SDK, вона змінюється.

## 6. Роадмап

### Фаза 0 — Дослідження API (СТАРТ ТУТ, без UI)

Мета: зрозуміти, що саме віддає Gemini, якої якості, і які ліміти.

- [ ] Створити ключ в AI Studio; зафіксувати в записах ліміти зі сторінки **AI Studio → Rate limit** для обраних моделей (RPM/TPM/RPD).
- [ ] `npx create-next-app@latest lexi` (TypeScript, App Router), додати `@google/genai`, `zod`.
- [ ] `lib/schema.ts`, `lib/gemini.ts` (промпт + схема + виклик + парсинг).
- [ ] `app/api/lookup/route.ts`; перевірка через `curl`:
  ```bash
  curl -s -X POST localhost:3000/api/lookup -H 'content-type: application/json' -d '{"query":"break the ice"}'
  ```
- [ ] `scripts/probe.ts`: прогнати набір із ~30 тестових запитів і вивести таблицю (query, type, confidence, latency, tokens, помилки).
- [ ] Тестовий набір має покривати: звичайні слова (`ubiquitous`), ідіоми (`break the ice`, `piece of cake`), фразові дієслова (`come across`, `put up with`), слова з помилками (`recieve`), багатозначні (`run`, `bank`), вигадане (`flibberjabbit`), українською мовою ввід, дуже довгий ввід, порожній.
- [ ] Заміряти: середню затримку, токени на запит, частку невалідного JSON.
- [ ] Навмисно навантажити (скрипт з паралельними запитами), щоб побачити, коли приходить `429`, і як виглядає відповідь (заголовки, `retryAfter`, повідомлення).
- [ ] Порівняти 2–3 моделі на тих самих запитах (якість перекладу, природність прикладів, галюцинації).
- [ ] Зафіксувати висновки в `FINDINGS.md`: обрана модель, реальні ліміти, цифри токенів, проблемні випадки, правки промпту.

**Критерій переходу до Фази 1:** якість карток влаштовує, невалідний JSON <2%, ліміти безкоштовного тарифу покривають типове використання (хоча б ~100 запитів на день), або рішення платити зафіксоване.

### Фаза 1 — Надійний бекенд

- [ ] Нормалізація query (`lib/normalize.ts`), обмеження довжини.
- [ ] Повторна спроба при невалідному JSON; таймаут запиту.
- [ ] Коректна обробка `429` (повідомлення + `retryAfter`).
- [ ] Прості rate-limit/захист ендпоінта (щоб чужий не спалив квоту): мінімум — секретний заголовок/пароль із env, перевірка на сервері.
- [ ] (Опц.) Серверний кеш в Upstash/Vercel KV.
- [ ] Юніт-тести на нормалізацію та парсинг схеми.

### Фаза 2 — UI

- [ ] Екран сесії: інпут, список карток, стани завантаження/помилки/ліміту.
- [ ] Компонент картки (тип, переклад, приклади, регістр, IPA).
- [ ] `lib/storage.ts`: `session` + `cache`; відновлення сесії після перезавантаження сторінки.
- [ ] Дії: видалити картку, повторити запит, редагувати.
- [ ] Клієнтський кеш: перед запитом перевіряти `lexi:cache`.

### Фаза 3 — Завершення сесії та PDF

- [ ] Генерація PDF (pdfmake/jsPDF) з кирилицею: заголовок із датою, список карток, приклади.
- [ ] Після успішного збереження PDF очищати `lexi:session` (з підтвердженням).
- [ ] Кнопка "Завантажити PDF без очищення" на випадок помилки.

### Фаза 4 — Деплой на Vercel

- [ ] Репозиторій у GitHub, імпорт у Vercel, env-змінні.
- [ ] Перевірка таймаутів serverless-функції (за потреби `maxDuration`).
- [ ] Перевірка, що ключ не потрапляє в клієнтський бандл.

### Фаза 5 — Розширення (за бажанням)

- [ ] Власний словник (збереження карток між сесіями), експорт/імпорт JSON.
- [ ] Supabase для синхронізації між пристроями.
- [ ] Озвучення (Gemini TTS модель або Web Speech API), IPA/аудіо зі словникових API.
- [ ] Повторення за інтервалами (SRS), прості вправи на основі карток.
- [ ] Пакетне додавання слів (список → batch).
